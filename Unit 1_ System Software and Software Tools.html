1. Language Processors

How source code becomes something a computer can run.

1.1Introduction

Language processor: a system program that converts source code (human-readable) into machine code (computer-executable).
  • Without language processors, writing programs directly in 0s and 1s would be very difficult.
  • Its primary role: convert a high-level source program into a machine-code target program.

1.3Fundamentals: Syntax and Semantics

Syntax: the form

The grammar and structure: keywords and rules for writing statements. Breaking a rule gives a syntax error.

Semantics: the meaning

What the syntax does. A program that runs but gives a wrong result has a semantic error.

if (condition) {
    statement;
}
// Syntax: the shape above; statements end with ;
// Semantics: execute the statement only if condition is true

Language gaps

Application domainproblem level
specification gap
Programming languageC, Java, Python
execution gap
Execution domainmachine instructions

Specification methods

  • Syntax: often written in BNF (Backus–Naur Form).
  • Semantics: described with formal systems such as set theory and Boolean algebra.

How a compiler stores information and memory.

2.1Search Data Structures

Store and quickly retrieve information about a program's elements.

StructureWhat it isSearch speed

Binary search treeHierarchical organisation of dataMuch faster than a list

Example: for int marks; the compiler adds a symbol table entry:
  • Name = marks
  • Type = int
  • Scope = local or global

2.2Allocation Data Structures

Manage memory during translation and execution.

Static
  • Assigned at compile time
  • For fixed-size data such as global variables
Analogy: a seat reserved in advance.
Stack
  • LIFO (last in, first out)
  • For function calls and local variables
  • Frame pushed on call, popped on return
Analogy: a stack of plates.
Heap
  • Allocated at runtime
  • For data of unknown size
  • Programmer requests and releases it
Analogy: an open playground.
int factorial(int n) {
    if (n == 0) return 1;
    else return n * factorial(n - 1);
}
// Each recursive call allocates a new stack frame.

int *p = (int*) malloc(sizeof(int));   // heap allocation

3.2Editors

Line editors

Old, command-based; edit a specific line by command. Example: ed in Unix.

Screen editors

Modern, graphical; edit the whole file at once. Examples: VS Code, Notepad++. Offer syntax highlighting, auto-completion, error detection.

3.3Debug Monitors

A debugger runs a program step by step to find logical errors (bugs).

  • Breakpoints: pause at a chosen line
  • Watch variables: check a value against what you expect
  • Memory inspection: view the program's memory
  • Step-by-step execution: one line at a time to trace the flow

Example: GDB (GNU Debugger), a command-line debugger for C and C++.

Quick Revision

Tap a question to check yourself.

Translation vs interpretation

Translation converts everything first and saves reusable object code (C). Interpretation executes line by line with no object code (Python).

Syntax vs semantics

Syntax is the form or grammar; semantics is the meaning. Broken syntax is a syntax error; wrong behaviour is a semantic error.

Specification gap vs execution gap

Specification gap: application domain to programming language. Execution gap: programming language to machine instructions.

Static vs stack vs heap

Static: compile time, fixed size. Stack: LIFO, function calls and locals. Heap: runtime, unknown size, programmer-managed.

Lex and Yacc

Lex builds the scanner that finds tokens. Yacc builds the parser for syntax analysis.

Search structures, slowest to fastest

Linear list, binary search tree, hash table. The symbol table is typically hash-based.

CLI vs GUI vs touch

CLI: typed commands. GUI: windows and icons. Touch: direct screen input.
